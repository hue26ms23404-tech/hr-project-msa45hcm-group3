# Gemini findings and changes

At baseline, `backend/app/core/config.py` defaulted to `GEMINI_ENABLED=false`, an empty key and `gemini-3.6-flash`; `.env.example` currently overrides the model with `gemini-3.5-flash-lite`. The old `google-generativeai` import emitted a deprecation warning in the baseline unit run. Date, report-filter and policy failures were silently converted to `None`, `{}` or fallback. Intent failure produced 503 without a provider category.

`app/ai/providers/gemini.py` now owns the only production SDK client and uses `google-genai` 2.x async `generate_content`, Pydantic response schemas, bounded timeouts and per-operation token limits. `readiness()` reports enabled/key-present/model/backend/environment/state without the key. Startup logs that safe metadata. Provider logs carry the existing audit request ID, operation, model, elapsed milliseconds, outcome and category. Categories distinguish disabled, model 404, authentication, quota, timeout, network, invalid response and schema rejection. Callers retain local fallback where applicable and record `FALLBACK_USED`.

`python -B -m app.ai.providers.diagnose` was executed locally: enabled=true, key_configured=true, model=`gemini-3.6-flash`, environment=`development`, state=`READY_TO_CHECK`; **no live call was made**. `--live` checks client initialization, model lookup (authentication/access), text generation and structured JSON separately. The local SDK version installed for tests was 2.30.1; `pip check` passed. [Google's SDK documentation](https://googleapis.github.io/python-genai/) supports explicit clients, async generation and Pydantic schemas.

Mock provider tests verify structured config, invalid output, disabled calls and timeout classification. They do not establish that the configured model exists or that the key can generate output. No Cloud Run CLI was available in this workspace; deployed image, revision, environment, secret and network remain staging checks. The provider model is never silently substituted.

# Follow-up and date findings

Baseline `requested_date` missed compound expressions, and the Gemini date phrase filter discarded relationship words. A failing regression captured “ngày thứ hai của tuần đầu tiên trong tháng tới” returning `None` at 2026-10-13. The old date/provider failure path returned `None` for both ambiguity and outage.

`app/ai/parsing/dates.py` returns `RESOLVED`, `AMBIGUOUS`, `INVALID` or `UNAVAILABLE`, plus value, RULE/GEMINI source and reason code. It handles explicit and relative Vietnamese dates, weekday weeks, first weekday in the next month, last weekday in a month, year boundaries and leap days. **Convention:** a month's first week begins on its first Monday; 2026-11-02 is the first Monday of November 2026. A month/week without a single day asks for a date. Clear ambiguity or invalid calendar input skips Gemini. Unresolved date-related input sends a bounded date phrase, without history, reason or unrelated account fields, then validates ISO output before writing only the draft date field.

`AIDraftService` remains account-owned with locked reads, 15-minute TTL and revision checks. A self lookup interruption uses a registered HR tool and returns the original draft ID/revision. On provider failure during a date follow-up, the API returns `UNAVAILABLE`/`AI_UNAVAILABLE` with the same draft ID and revision; the modal offers retry and also suggests entering an explicit date. Empty answers after a report-provider failure likewise leave its draft revision unchanged. Tests cover the prescribed 2026 dates, invalid and ambiguous dates, year/leap boundaries, owner-bound follow-ups, provider timeout, stale revisions and report follow-up without an update. Live Gemini semantic interpretation and full browser-to-database multi-turn flow remain unverified.
